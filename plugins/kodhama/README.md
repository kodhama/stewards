# Kodhama

Adds verified Claude Code or Codex marketplace setup to repository-owned GitHub
Actions workflows. You point it at the jobs that invoke a host CLI; it writes the
exact, host-native marketplace registration those jobs need, before they run.

It edits workflow configuration and nothing else. It is not installed into the
resulting CI job, and it provides no shared action, runtime, container, or
installer.

## Where this works, and what that claim rests on

**Support is not claimed.** Kodhama is dogfood: it is used by the family's own
maintenance repository while that family is still learning from it. Catalog
presence, a successful install, and green CI do not amount to a support promise,
and none of them is offered as one.

What is actually checked, on every pull request that touches this plugin:

| Host | What runs | What it establishes |
|---|---|---|
| **Claude Code** | `scripts/keyless_admission_check.py` | The host validates the manifest with no warnings, adds a local marketplace carrying this commit's payload, installs the plugin from it, and reports the declared skill in its component inventory. No API key, no model turn. |
| **Codex** | `codex plugin marketplace add` against this repository at the tested commit | The host accepts the catalog and resolves the marketplace root to the checkout under test. |

**What none of that establishes**, stated because the difference matters: that the
skill *runs*. Measured rather than assumed — the host lists a skill directory in
its inventory even when `SKILL.md` carries no frontmatter at all, so the Claude
check is closer to a layout check than a load check. Confirming behaviour needs a
model turn, which costs a key. `kodhama-0018` §3 says the admission evidence *"may
be"* a package and invocation test, not that it must be; this meets the package
half and leaves the invocation half openly unmet.

Nothing here is checked on any other host, or on Claude Code's cloud, headless,
GitHub Action, or SDK surfaces.

## Why there is no surface matrix

There used to be a `surfaces.json` here, plus a schema, a validator, and a frozen
snapshot of one CI run's observations. Nothing read any of it: the validator
checked the file against itself, and the test checked that the validator did.

`kodhama-0025` retired it family-wide. The question a reader actually has — *does
this work on my host?* — is answered better by a check that ran this morning than
by a row that has said `pending` since it was written. The table above is
generated by nobody and maintained by hand, and it is smaller than what it
replaced.
